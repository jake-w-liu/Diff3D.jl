Controls, Animation and Helpers

Camera and object controls, clocks, keyframe tracks, clips, the animation mixer and scene helpers.

Diff3D.AnimationMixer — Type
AnimationMixer(clip; loop=clip.loop, repetitions=clip.repetitions,
               clamp_when_finished=clip.clamp_when_finished,
               time_scale=clip.time_scale, zero_slope_at_start=true,
               zero_slope_at_end=true)

Plays clip on its tracks' targets like a three.js AnimationMixer driving the one action of clipAction(clip).play() (src/animation/AnimationAction.js, AnimationMixer.js, PropertyMixer.js).

mixer_update!(mixer, dt) advances the mixer by dt * time_scale seconds and steps the action like AnimationAction._updateTime: :repeat and :pingpong count every loop crossed in either direction (playing backward from zero the first wrap is free), and after repetitions loops (-1: unlimited) or at either end of a :once clip the action finishes. With clamp_when_finished a finished action pauses on its last pose (paused becomes true); otherwise it is disabled (enabled becomes false) and every animated property returns to its original value, the value it had when the mixer was created or last mixer_play!ed (three.js PropertyMixer.saveOriginalState). A finished action stays finished whatever the later dt; mixer_reset! and mixer_set_time! restart it, and mixer_stop! restores the original values and stops applying the clip.

zero_slope_at_start/zero_slope_at_end (three.js zeroSlopeAtStart/ zeroSlopeAtEnd) select zero-slope (true) or zero-curvature (false) endings for :cubic tracks at the clip start of the first loop and the clip end of the last; :pingpong always uses zero slope. As in three.js, a cubic track keeps the endings it had when its sample entered the current key interval.

The fields time (mixer time), loop, repetitions, clamp_when_finished, time_scale, zero_slope_at_start, zero_slope_at_end, enabled and paused may be changed between updates, as on a three.js action; the action's clip-local time is action_time. Unlike three.js, an enabled action writes its sampled values on every update, also when they did not change since the previous frame.

Diff3D.Clock — Type
Clock(auto_start::Bool=true)

Frame timer modelled on three.js Clock (src/core/Clock.js), in seconds. Fields: start_time (time of the last start), last_time (three.js oldTime), elapsed_time (time accumulated while running), running and auto_start.

Clock() starts at construction, so start_time is set immediately and the first clock_delta! returns the time since construction (three.js starts on the first getDelta, which returns 0). Clock(false) is created stopped: clock_delta! returns 0 until clock_start!. A stopped clock with auto_start set restarts on the next clock_delta!, which returns 0, as three.js does; clock_stop! clears auto_start.

Every now argument defaults to the current monotonic time in seconds; pass it explicitly for deterministic stepping.

Diff3D.FrameTimer — Type
FrameTimer(now=current time) -> FrameTimer

Frame timer modelled on three.js Timer (src/core/Timer.js), the r183 replacement for Clock, in seconds. Call timer_update! once per frame, then read the frame's timer_delta and the accumulated timer_elapsed; reading never changes the timer. time_scale (three.js setTimescale) scales every later delta. The Page Visibility hook of three.js (connect/disconnect) has no headless counterpart.

Fields: start_time (absolute), previous_time and current_time (relative to start_time), delta, elapsed and time_scale.

Diff3D.OrbitControls — Method
OrbitControls(camera[, target]; enabled=true, enable_rotate=true,
              enable_zoom=true, enable_pan=true, enable_damping=false,
              damping_factor=0.05, min_distance=0.0, max_distance=Inf,
              min_polar_angle=0.0, max_polar_angle=π,
              min_azimuth_angle=-Inf, max_azimuth_angle=Inf,
              screen_space_panning=true, min_zoom=0.0, max_zoom=Inf,
              auto_rotate=false, auto_rotate_speed=2.0,
              cursor=Vec3(0.0, 0.0, 0.0), min_target_radius=0.0,
              max_target_radius=Inf)

Orbit/pan/zoom camera control state matching three.js OrbitControls for a PerspectiveCamera or an OrthographicCamera. The camera orbits the target about camera.up. Dollying a perspective camera scales its distance to the target; dollying an orthographic camera divides camera.zoom by the factor, clamped to [min_zoom, max_zoom], and leaves the camera in place (three.js minZoom/maxZoom). With auto_rotate=true, orbit_update! also turns the camera about camera.up at auto_rotate_speed (three.js autoRotate). Every interaction and update keeps the target between min_target_radius and max_target_radius from cursor (three.js minTargetRadius, maxTargetRadius, cursor).

A divisions×divisions grid of size size on the xz-plane, with the vertex order of three.js GridHelper: for each offset k from -size/2, a line parallel to x and then one parallel to z. Diff3D.PolarGridHelper — Function

Polar grid on the xz-plane: rings concentric circles out to radius and sectors evenly spaced radial spokes (three.js PolarGridHelper). Circles are approximated by circle_segments chords each. As in three.js, spokes start on +z and advance toward +x, a single sector draws no spoke, and rings are listed from the outermost inward. Odd-numbered spokes and rings (counting from 0) take color1 and the others color2, as a per-vertex :color attribute with three.js's defaults 0x444444 and 0x888888; passing color draws every line in that one colour instead.

Diff3D.SkeletonHelper — Method
SkeletonHelper(skeleton; color=nothing, color1=Color3(0,0,1), color2=Color3(0,1,0))

Line segments connecting each bone to its parent bone in world space (three.js SkeletonHelper). Bones whose parent is not itself a bone in the skeleton are skipped, matching three.js which only links bone-to-bone. As in three.js each segment runs from the bone (color1, blue) to its parent (color2, green) with per-vertex :colors, and the material neither tests nor writes depth, so the skeleton draws over the mesh. Passing color draws every segment in that one colour instead.

Diff3D.clock_elapsed — Function
clock_elapsed(clock[, now]) -> Float64

Seconds the clock has run up to now: the accumulated elapsed_time plus, while running, the span since the last clock_delta!. A stopped clock returns its accumulated time. Diff3D.interpolate_catmull_rom — Method
interpolate_catmull_rom(times, values, t)

Smooth cubic sample of values at strictly increasing times, evaluated at t and clamped to the endpoints. This is three.js CubicInterpolant (InterpolateSmooth) with its default zero-curvature endings: interior tangents average the slopes of the two adjacent intervals, which reduces to uniform Catmull-Rom on evenly spaced keys. values may be reals or Vec3.

Diff3D.orbit_update! — Function
orbit_update!(oc[, delta_time])

Advance the orbit by one frame. Like three.js OrbitControls.update, every call re-applies the distance, polar, azimuth, and target-radius limits (and min_zoom/max_zoom for an orthographic camera), so a camera that starts (or is left by a changed limit) outside them moves back inside; a camera already inside them is not moved. With damping disabled nothing else happens (interactions apply immediately). With damping enabled it applies damping_factor of the residual rotation, dolly, and pan velocities, then decays them by (1 - damping_factor) so motion eases to a stop after the last interaction and the total converges to the queued deltas. Velocity components below a small threshold are zeroed to avoid endless drift.

With oc.auto_rotate set, each call first turns the camera about camera.up by 2π/60 * auto_rotate_speed * delta_time radians, or by 2π/3600 * auto_rotate_speed when delta_time (seconds) is omitted, as three.js does per frame (_getAutoRotationAngle); with damping enabled that turn is added to the residual azimuth velocity instead.

Diff3D.track_scale! — Method
track_scale!(track, time_scale) -> track

Multiply every key time of track by time_scale, in place (three.js KeyframeTrack.scale); the values, and the tangents of cubic-spline tracks, are unchanged, as in three.js. time_scale must be positive (Diff3D keys stay strictly increasing); otherwise, or if a time overflows, an ArgumentError is thrown and the track is unchanged.

Diff3D.track_shift! — Method
track_shift!(track, time_offset) -> track

Add time_offset seconds to every key time of track, in place (three.js KeyframeTrack.shift). Like three.js it changes the time vector itself, so tracks that share that vector move together. Throws ArgumentError, leaving the track unchanged, if the shifted times are not finite and strictly increasing.

Diff3D.track_validate — Method
track_validate(track) -> Bool

Whether track is still a valid track after in-place edits of its vectors, like three.js KeyframeTrack.validate: it has keys, one value (and tangent) per key, and its times are in increasing order. Diff3D tracks are stricter than three.js here, as their constructors are: times and values must be finite (three.js only rejects NaN) and two keys may not share a time.
