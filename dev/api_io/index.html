Diff3D.save_webgl_html — Method
save_webgl_html(path, cases; title="Diff3D.jl Live WebGL Showcase", chrome=true)

Export one or more WebGLExportCases to a standalone interactive HTML file. The browser runtime is intentionally small; the scene data is produced from Diff3D.jl objects, materials, instancing, and optional AnimationClips. With chrome=false, the header, playback controls, stats, case list, and title bar are hidden via CSS (DOM ids retained for the JS runtime), leaving a canvas-only page. A title that HTML cannot carry unchanged (one containing U+0000, or invalid Unicode) throws an ArgumentError.

The complete export replaces path only after serialization succeeds. A failed export leaves an existing destination intact. A destination symlink is replaced without changing its target. On POSIX systems, existing regular-file permission bits are preserved and new output files use owner-only read/write permissions.

Diff3D.load_obj — Method
load_obj(path) -> BufferGeometry

Load a Wavefront OBJ mesh (vertices, texture coordinates, normals, and faces; polygons fan-triangulated). Normals are taken from the file when present; a corner without a usable file normal (no vn reference, or a zero vn) gets its face normal, and a file without normals gets compute_vertex_normals!. Materials are ignored.

As in three.js OBJLoader, a line ending in a backslash continues on the next line, and vertex records written as v x y z r g b add a per-vertex :color attribute, with the sRGB channels converted to linear. Colours are kept only when every vertex that a face references carries one (otherwise three.js builds a colour attribute that does not line up with the corners).

Diff3D.load_ply — Method
load_ply(path; property_name_mapping=Dict{String,String}(),
         custom_property_mapping=Dict{Symbol,Vector{String}}()) -> BufferGeometry

Load a Stanford .ply mesh (ASCII, binary_little_endian, or binary_big_endian) like three.js PLYLoader. Reads the vertex element and the face element (a vertex_indices or vertex_index list per face). Vertex properties are found by the names PLYLoader accepts: x|px|posx (likewise y, z), nx|normalx (likewise ny, nz), s|u|texture_u|tx and t|v|texture_v|ty for uvs, and red|diffuse_red|r|diffuse_r (likewise green, blue). A quad face splits into triangles (0,1,3) and (1,2,3) as in PLYLoader; larger polygons, which PLYLoader drops, are fan-triangulated.

Colours are read as sRGB and stored linear, as PLYLoader does; an integer channel is first divided by the maximum of its declared type. A face element with a texcoord list (two values per corner) or red/green/blue properties gives every triangle corner its face's texture coordinate or colour; the geometry is then non-indexed, as PLYLoader makes it with toNonIndexed, and those values replace any vertex uvs or colours.

property_name_mapping renames file properties before they are matched, like PLYLoader.setPropertyNameMapping (for example Dict("diffuse_red" => "red")). custom_property_mapping adds vertex attributes, like PLYLoader.setCustomPropertyNameMapping: each entry name => ["prop_a", "prop_b"] stores those scalar vertex properties, unscaled, as attribute name with one component per listed property. Every listed property must exist.

Returns a BufferGeometry with positions, uvs when present, normals (file normals when present, otherwise smooth normals from compute_vertex_normals! on the indexed mesh), and a :color attribute when colours are present.

Diff3D.load_stl — Method
load_stl(path) -> BufferGeometry

Load an STL mesh, auto-detecting binary vs ASCII. Each triangle contributes three independent vertices; call compute_vertex_normals! afterward for smooth shading.

A binary file whose header contains a COLOR=rgba sequence gets a per-vertex :color attribute, as in three.js STLLoader: each facet uses its own 5-bit RGB from the attribute word when bit 15 is clear, and the header colour otherwise. Colours are converted from sRGB to linear. The header alpha byte is not stored.

Diff3D.parse_xyz — Method
parse_xyz(text; source="<string>") -> BufferGeometry

Parse XYZ point-cloud text using the same two record layouts as three.js XYZLoader: x y z and x y z r g b. RGB channels are interpreted as sRGB bytes in [0,255] and stored as a linear :color vertex attribute. Empty lines and full-line # comments are ignored. Unlike the current three.js parser, malformed field counts, mixed XYZ/XYZRGB records, non-finite values, and out-of-range RGB bytes throw ArgumentError with line context instead of being silently ignored or propagated into geometry buffers.

Diff3D.save_obj — Method
save_obj(path, geo; name="") -> path

Write geo as a Wavefront OBJ file laid out like three.js OBJExporter for one mesh: o name, the v records, vt records when geo.uvs is set, vn records (normalized) when geo.normals is set, then one f record per triangle using the v/vt/vn, v//vn or v/vt form that matches. Values are written at full Float64 precision. Round-trips with load_obj.

Diff3D.save_ply — Method
save_ply(path, geo; binary=false, little_endian=false) -> path

Write geo as a Stanford PLY file laid out like three.js PLYExporter: double x/y/z, then nx/ny/nz (normalized) when geo.normals is set, s/t when geo.uvs is set, and red/green/blue when the geometry has a :color attribute, followed by a vertex_index list of 0-based triangle indices. Colours are converted from linear to sRGB, as PLYExporter does. binary selects binary_little_endian or binary_big_endian (the PLYExporter default) by little_endian.

Diff3D.TextGeometry — Method
TextGeometry(font, text; size=1.0, curve_segments=8, depth=0.0,
             bevel_enabled=false, bevel_size=0.0,
             bevel_thickness=bevel_size, bevel_segments=1)

Build a flat or extruded BufferGeometry from loaded typeface JSON outlines. Glyph contours are grouped into outer loops and holes by the nonzero rule before triangulation. With beveling enabled the bevel follows three.js ExtrudeGeometry: the lids keep the glyph outline at z = -bevel_thickness and z = depth + bevel_thickness, and bevel_segments rings per side grow the outline by up to bevel_size towards the body, which spans z = 0 to depth.

Diff3D.TextureLoader — Method

Load a PNG, JPEG/JPG, or uncompressed KTX2 image into a [Texture].

PNG and JPEG textures default to sRGB. KTX2 textures infer linear or sRGB from their Vulkan format. Single-channel and two-channel KTX2 images are expanded to RGB using Vulkan's zero defaults for missing color components, and KTXswizzle component mappings are honored. An explicit colorspace keyword overrides the default.

Diff3D.inflate — Method
inflate(data; max_output=nothing) -> Vector{UInt8}

Decompress a raw DEFLATE stream (RFC 1951, no zlib header). Decoding stops after the final block; bytes after it are ignored. Malformed streams, including Huffman code sets that are over-subscribed or incomplete, raise an error. A non-negative max_output bounds the decompressed size: a stream that would produce more bytes raises an error.

Diff3D.load_exr — Method
load_exr(path) -> Array{Float64,3}

Decode an OpenEXR scanline or tiled image into a linear, unclamped H×W×3 RGB array. Tiled images may be ONE_LEVEL or MIPMAP_LEVELS (the full-resolution level 0 is returned). A single Y luminance channel is replicated across RGB (matching three.js). Supports NONE, RLE, ZIP, ZIPS, PIZ, PXR24, and B44/B44A compression and HALF/FLOAT/UINT channels (PXR24/B44 cover HALF/FLOAT, matching three.js). Deep, multi-part, RIPMAP tiles, subsampled, pLinear-B44, and DWA payloads raise a clear error rather than being approximated.

Diff3D.load_glb — Method
load_glb(path) -> Scene

Load a binary glTF (.glb) container into a Scene. Parses the 12-byte header (magic glTF, version, total length) and the chunk list, extracts the JSON chunk (type 0x4E4F534A) and the optional binary chunk (type 0x004E4942), then reuses the glTF document logic. A buffer view without a uri reads from the embedded binary chunk (buffer 0). Mirrors load_gltf output.

Diff3D.load_gltf — Method
load_gltf(path) -> Scene

Load a text glTF 2.0 file into a Scene.

Supports data-URI and external buffers, node transforms, cameras, punctual lights, mesh primitives, basic PBR metallic-roughness materials, skin binding, morph targets, and texture references supported by Diff3D's built-in loaders. Authored translation, rotation, and scale components are preserved for animation, including zero and negative scales. Animated nodes must not define matrix. A triangle primitive without NORMAL is shaded flat, as glTF requires: its geometry is de-indexed so that every triangle has its own corners carrying the triangle's face normal. Use load_glb for binary .glb containers whose first buffer is stored in the GLB BIN chunk.

source
Diff3D.load_gltf_asset — Method
load_gltf_asset(path) -> GLTFAsset

Load a glTF 2.0 file and return both the scene and parsed animation clips. Node translation, rotation, and scale channels are mapped to Diff3D.jl KeyframeTrack / QuaternionKeyframeTrack objects targeting the loaded scene nodes, and weights channels drive morph-target influences. Use load_glb_asset for binary .glb containers.

Diff3D.load_mtl — Method
load_mtl(path) -> Dict{String, MeshPhongMaterial}

Parse a Wavefront .mtl file like three.js MTLLoader: keywords are case-insensitive and newmtl names are the rest of the line. Reads Kd (diffuse), Ks (specular), Ns (shininess), Ke (emissive), d/Tr (opacity: as in MTLLoader, the last d and the last Tr of a material are applied in the order their keywords first appear, and only d below 1 or Tr above 0 sets the opacity, to d or 1 - Tr; a d below 0 or a Tr above 1, which would give a negative opacity, is an error), and the texture maps map_Kd (map), map_Ks (specular_map), map_Ke (emissive_map), norm (normal_map), and map_d (alpha_map, which also makes the material transparent). Kd, Ks and Ke are sRGB and stored linear, as MTLLoader converts them. As in MTLLoader, the last statement of each kind wins, and only that map's texture is loaded; texture -s and -o options set the texture repeat and offset. Other statements, such as Ka, illum, bump, and disp, are ignored.

Diff3D.load_obj_scene — Method
load_obj_scene(path) -> Group

Load a Wavefront OBJ file as a scene, like three.js OBJLoader.parse: a Group with one child per o/g object that has geometry, named after the object. Faces become Mesh children with the geometry load_obj builds for them (one mesh per usemtl material of the object), l polylines become LineSegments and p points become PointsObjects. Materials come from the mtllib libraries as in load_obj_groups. As with OBJLoader given those libraries through setMaterials, a file with a library gives every mesh its library material (a default MeshPhongMaterial for a name the library lacks or for faces before any usemtl), lines a LineBasicMaterial and points a PointsMaterial (size 10, size_attenuation=false) that copy its colour and opacity, and vertex colours are not used. Without a library, as with OBJLoader alone, meshes get a MeshPhongMaterial with vertex_colors set when the file has vertex colours, lines a default LineBasicMaterial, and points a PointsMaterial of size 1 (size_attenuation=false) coloured by their vertex colours. A file with vertices but no faces, lines or points loads as one unnamed point cloud.

Unlike OBJLoader, which draws the vertices of a polyline l a b c pairwise, a polyline becomes the segments a-b and b-c, and the faces, lines and points of one object become separate children instead of one object of the last kind. Smoothing groups (s) are ignored.

Diff3D.save_gltf — Method
save_gltf(path, object; animations=AnimationClip[], binary=endswith(lowercase(path), ".glb"))

Write object as a glTF 2.0 file, like three.js GLTFExporter.parse. A Scene gives the glTF scene its visible children as root nodes; any other exportable object becomes the only root node. With binary=true the file is a .glb container; otherwise it is JSON with the buffer embedded as a base64 data URI. load_gltf_asset and load_glb_asset read the result back (with each mesh node loaded as a Group holding its primitive).

Exported: Group, Object3D, Mesh, LineSegments, LineObject, LineLoop and PointsObject nodes with their names and transforms (hidden objects are left out, as with GLTFExporter's default onlyVisible); positions, normals (normalised), uvs, :uv2, :tangent, :color (for a mesh only when its material uses vertex colours), indices, morph targets, morph influences and target names; untextured MeshStandardMaterial, MeshBasicMaterial (as KHR_materials_unlit), Phong, Lambert, line and points materials (colour, opacity, alpha mode and cutoff, double side, emissive, with KHR_materials_emissive_strength); and AnimationClips whose tracks are position, scale, rotation and morph-weight keyframes (linear, step or cubic spline). Line widths, point sizes and depth flags are not part of glTF and are not written.

Anything else raises an ArgumentError instead of being dropped: cameras, lights, skinned and instanced meshes, sprites, textures, physical, toon and shader materials, back-side or wireframe materials, geometry groups, draw ranges, flat_shading=true, custom attributes, and other track kinds.
