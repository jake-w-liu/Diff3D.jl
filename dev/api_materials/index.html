Materials, Textures and Lights

Materials, textures and sampling, lights, shadow maps and shading functions.

Diff3D.PMREM — Type

Prefiltered radiance environment map: a sequence of CubeTexture levels where level i (0-based) holds the source convolved with a GGX specular lobe of roughness i / (levels-1). Level 0 is the mirror (roughness 0) reflection. Build one with generate_pmrem and sample it with sample_pmrem.

Diff3D.equirectangular_to_cubemap — Method
equirectangular_to_cubemap(tex; size=max(1, min(H, W ÷ 2)),
                           generate_mipmaps=false) -> CubeTexture

Convert an equirectangular environment texture to a six-face CubeTexture using Diff3D's cube-map face convention (+x, -x, +y, -y, +z, -z). The source texture is sampled as longitude/latitude with horizontal wrap and vertical top/bottom poles; HDR values are preserved as floating-point data. Set generate_mipmaps=true to build per-face mip chains for roughness-aware environment sampling.

Diff3D.generate_pmrem — Method
generate_pmrem(ct; levels=5, samples=64, base_size=face size) -> PMREM

Prefilter a CubeTexture into a roughness mip chain, mirroring three.js' PMREMGenerator. Level i is convolved with a GGX lobe of roughness i / (levels-1) using a deterministic Hammersley sequence (no RNG), and each level's face resolution halves so rougher levels are cheaper. HDR/linear values are preserved. Sample the result with sample_pmrem.

Diff3D.sample_texture — Method
sample_texture(tex, u, v) -> Color3

Sample the texture at UV (u,v) after its UV transform (tex.matrix), with coordinates outside [0,1]² handled by the wrap modes. v=0 is the bottom row. Filtering follows the WebGL rules: :nearest reads texel (floor(u·W), floor(v·H)) with the wrap mode applied to that texel index, and :bilinear blends the four texels around (u·W − ½, v·H − ½). Returns the raw stored values; see sample_texture_linear for color-space decoding.

source
Diff3D.sample_texture_aniso — Method
sample_texture_aniso(tex, u, v, du, dv; max_aniso=8) -> Color3

Anisotropic texture filtering. (du, dv) is the per-pixel UV-space footprint (the texel span one screen pixel covers along the U and V axes, expressed as a fraction of the [0,1] UV range, exactly the convention used by sample_texture_auto's duv). The footprint is modeled as an axis-aligned ellipse with half-extents |du| and |dv|; its major axis is the larger extent and its minor axis the smaller.

The sample count is N = clamp(ceil(major/minor), 1, max_aniso). N probes are spread evenly along the major axis, centred on (u, v), each taken at the level-of-detail implied by the minor axis footprint (via sample_texture_auto, which reuses the existing mipmaps). Averaging these probes integrates the long direction of the footprint while keeping the short direction sharp, which is exactly what isotropic bilinear/mip sampling blurs away at grazing angles.

Fallback behaviour:

  • If tex has no mipmaps, or the footprint is (near-)isotropic (ratio < 1.5), or max_aniso <= 1, a single isotropic sample is returned (sample_texture_auto when mipmaps exist, else sample_texture).

AD tolerance: the discrete decisions (N, the per-probe integer mip level) are made on Float64 magnitudes, while the probe coordinates, the minor-axis duv, and the averaging weight 1/N all flow through unchanged, so a ForwardDiff.Dual/ADVar (u, v, du, dv) keeps a smooth derivative through the returned color.

Diff3D.sample_texture_auto — Method
sample_texture_auto(tex, u, v, duv) -> Color3

Sample with automatic magnification/minification selection from the per-pixel UV footprint duv (the maximum texel span covered by one screen pixel, as a fraction of the [0,1] UV range). Magnifying footprints use mag_filter. Minifying footprints use the continuous LOD

lod = clamp(log2(max(duv * size, 1)), 0, length(mipmaps))

with size = max(W, H) the base texel dimension, mirroring the GPU mipmap selection used by three.js. The two bracketing integer levels are sampled with sample_texture_lod and trilinearly blended by the fractional part of lod. When the texture has no mipmaps the call falls back to the base level using the texture's minification filter. The four mipmap minification filters are honored: nearest/linear texel filtering is selected from the filter prefix, and nearest/linear mip-level selection is selected from the filter suffix. The integer level choice is a discrete decision, but the linear mip blend weight is carried through unchanged so the result stays smooth for ForwardDiff.Dual/ADVar duv.

Diff3D.sample_texture_linear — Method
sample_texture_linear(tex, u, v) -> Color3

Sample the texture and return the color in linear light. When tex.colorspace === :srgb every texel's RGB is converted with the standard sRGB→linear transfer function (c ≤ 0.04045 ? c/12.92 : ((c+0.055)/1.055)^2.4) before the texels are filtered, as GL decodes the SRGB8_ALPHA8 textures three.js uploads for SRGBColorSpace color maps. When tex.colorspace === :linear the raw sample is returned unchanged (for data textures such as normal, roughness, metalness, AO, or depth maps). sample_texture itself is left untouched and always returns the raw stored values.

sample_texture_linear(tex, u, v, duv) -> Color3

The same with the automatic magnification/minification and mip-level selection of sample_texture_auto: sRGB texels are decoded before the bilinear and the between-level (trilinear) blends.

Diff3D.LightProbe — Type
LightProbe(; coeffs=(4 × Color3(0)), sh=(9 × Color3(0)), intensity=1.0, name="LightProbe")
LightProbe(ambient::Color3; intensity=1.0)

Ambient light probe whose irradiance depends on the surface normal n (world space).

  • sh holds the nine coefficients of a three.js SphericalHarmonics3 (LightProbe.sh, order L00, L1-1, L10, L11, L2-2, L2-1, L20, L21, L22) in radiance units. They contribute three.js shGetIrradianceAt(n) (SphericalHarmonics3.js getIrradianceAt, lightsparsbegin.glsl.js). Build them from an environment with light_probe_from_cube_texture.
  • coeffs is Diff3D's order-1 form (DC, x, y, z), contributing DC + x·n.x + y·n.y + z·n.z directly as irradiance.

The irradiance is the coeffs term clamped to be non-negative per channel plus the sh term, which is not clamped (three.js adds shGetIrradianceAt to the fragment irradiance unclamped, so ringing of a band-limited probe can subtract light), scaled by intensity; it adds to the same ambient irradiance as AmbientLight. LightProbe(ambient) is a uniform probe with coeffs[1] = ambient. The compact WebGL export supports only coeffs and rejects a probe with non-zero sh.

Diff3D.light_probe_from_cube_texture — Method
light_probe_from_cube_texture(cube::CubeTexture; intensity=1.0) -> LightProbe

Project a radiance environment onto nine spherical-harmonic coefficients and return a LightProbe carrying them in sh, following three.js LightProbeGenerator.fromCubeTexture (examples/jsm/lights/LightProbeGenerator.js): every texel is weighted by its solid angle 4 / |c|^3 (c the texel centre on the unit cube), accumulated against the SphericalHarmonics3.getBasisAt basis, and the sum is normalized by 4π / Σweight. Faces with colorspace=:srgb are decoded to linear first, :linear faces are used as stored.

Each face must be square (faces may differ in size). Texel directions follow sample_cube, so the probe lights a surface the way the same cube map reflects onto it. three.js mirrors the x axis for a CubeTexture built from images (flipEnvMap), so for the same six images its coefficients sh[4], sh[5] and sh[8] (the basis functions odd in x: L11, L2-2, L21) have the opposite sign; three.js fromCubeRenderTarget, which reads unmirrored faces, agrees with this function.

Diff3D.parse_ies — Method
parse_ies(text) -> IESProfile

Parse an IESNA LM-63 photometric data file (the .ies format emitted by lamp manufacturers and supported by three.js' IESLoader). The parser reads the TILT= line, any TILT=INCLUDE tilt table (skipped, as in three.js), the 13-value control block, then the vertical-angle vector and the candela values, supporting the common single-horizontal-plane (rotationally symmetric) case. Multi-plane files are collapsed to their first horizontal plane. Keyword/label lines beginning with [ are ignored. Values may be separated by whitespace or commas and may wrap across lines.

The numeric layout after the TILT= data is:

<num_lamps> <lumens_per_lamp> <candela_multiplier> <num_vertical> <num_horizontal>
    <photometric_type> <units_type> <width> <length> <height>
<ballast_factor> <future_use> <input_watts>
<vertical_angles...>      (num_vertical values)
<horizontal_angles...>    (num_horizontal values)
<candela values...>       (num_vertical × num_horizontal, plane-major)

Candela values are scaled by candela_multiplier when it is positive; a non-positive multiplier leaves them unscaled.

Diff3D.ShadowMap — Type
ShadowMap(depth, light_vp, bias, pcf_radius=0; intensity=1.0, normal_bias=0.0)

Light-space depth map queried by shadow_visibility. depth holds NDC depth from the light (smaller is nearer, Inf marks an empty texel) sampled through the view-projection light_vp; bias is subtracted from a receiver's NDC depth before the comparison and pcf_radius selects percentage-closer filtering.

intensity (three.js LightShadow.intensity, in [0, 1]) scales how dark the shadow is: a query returns mix(1, lit_fraction, intensity). normal_bias (three.js LightShadow.normalBias, world units) offsets a query point along the surface normal passed to shadow_visibility before the depth test.

compute_shadow_map returns a cube map for a PointLight: depth then stores the six square faces side by side (res × 6res, faces ordered +X, -X, +Y, -Y, +Z, -Z as in three.js), each rendered by its own 90° camera, and light_vp is the +X face camera.

source
Diff3D.compute_shadow_map — Method
compute_shadow_map(scene, light; resolution=512, bias=nothing, pcf_radius=nothing, clipping_planes=_NO_PLANES)

Render the scene's depth from light's viewpoint into a [ShadowMap].

Directional and spot lights render one resolution × resolution map. A PointLight renders a cube map, one resolution × resolution face per axis direction, so casters on every side of the light shadow (three.js PointLightShadow).

pcf_radius selects percentage-closer filtering (PCF) soft shadows when querying the map with shadow_visibility: a value r samples a (2r+1)x(2r+1) neighbourhood of the depth map and returns the lit fraction in [0,1]. When pcf_radius or bias is nothing, three.js-style per-light shadow_pcf_radius or shadow_bias settings are used when present; otherwise the historical hard shadow (pcf_radius=0) and bias=3e-3 defaults are preserved.

source
Diff3D.shadow_visibility — Method
shadow_visibility(sm, p; pcf_radius=sm.pcf_radius, normal=nothing)

Visibility of a world-space point from the shadow map's light: 1 lit, 0 fully occluded. With pcf_radius = r > 0, a (2r+1)x(2r+1) neighbourhood of the projected texel is sampled and the lit fraction in [0,1] is returned, giving a soft penumbra (percentage-closer filtering, matching three.js PCFShadowMap). The neighbourhood is clamped to the map bounds (to the sampled face of a point-light cube map). pcf_radius=0 reproduces the single-sample hard shadow exactly.

The result is mix(1, visibility, sm.intensity) (three.js getShadow). When a unit surface normal is given, the lookup point is first moved to p + normal * sm.normal_bias (three.js shadowmap_vertex). The CPU renderers pass the shaded surface normal, which includes any normal-map perturbation, where three.js uses the interpolated vertex normal.

source

Diff3D.shade_pbr — Function
shade_pbr(normal, light_dir, view_dir, light_color, light_intensity,
          albedo, metalness, roughness, specular_intensity=1.0,
          specular_color=Color3(1.0, 1.0, 1.0)) -> Color3

Physically based response to one light, following three.js RE_Direct_Physical for a metallic-roughness surface with an index of refraction of 1.5: GGX distribution (D_GGX), height-correlated Smith visibility (V_GGX_SmithCorrelated), Schlick Fresnel (F_Schlick), the DFG-table multiple-scattering compensation and a BRDF_Lambert diffuse term weighted by 1 - F, all scaled by the irradiance N·L · light. roughness is clamped to [0.0525, 1] like three.js; specular_intensity and specular_color act as in KHR_materials_specular. view_dir points from the surface toward the camera and light_dir from the surface toward the light.

source
