Diff3D.euler_from_rotation_matrix — Function
euler_from_rotation_matrix(m, order=:XYZ)

Intrinsic Euler angles, in the given order, of the pure rotation in the upper-left 3×3 block of m (three.js Euler.setFromRotationMatrix). When the sine of the middle angle is within 1e-7 of ±1 (the middle angle within about 4.5e-4 radians of ±π/2), three.js sets one of the other angles to zero, which only approximates m; this function instead returns coupled angles that reproduce m, so the angles differ from three.js in that band.

Each face camera's projection_matrix(c) * view_matrix(c) equals that of three.js CubeCamera in the WebGL coordinate system, whose face cameras use fov = -90 with up vectors (0,1,0), (0,1,0), (0,0,-1), (0,0,1), (0,1,0), (0,1,0); Diff3D expresses the same transform with a positive field of view and negated up vectors.

render! stores image rows top-down, whereas WebGL stores a render-target face bottom-up. To use a face render as a CubeTexture face in the three.js/WebGL cube layout sampled by sample_cube, reverse its rows, e.g. Texture(reverse(target.color; dims=1); colorspace=:linear) (render! writes linear colors).

Diff3D.PerspectiveCamera — Type
PerspectiveCamera(; fov=π/4, aspect=1.0, near=0.1, far=1000.0, zoom=1.0,
                  focus=10.0, film_gauge=35.0, film_offset=0.0,
                  name="PerspectiveCamera", rotation_driven=false)

Perspective camera with a vertical field of view fov in radians. It is aimed through its position, target and up fields (or its rotation when rotation_driven). As in three.js PerspectiveCamera, zoom scales the image, film_gauge (mm) and film_offset (mm, horizontal) describe the film used by get_focal_length and the off-axis film shift, focus is the object distance used by StereoCamera, and view holds an optional CameraView set with set_view_offset!. projection_matrix follows three.js updateProjectionMatrix for every combination of these properties. An infinite far gives the limiting infinite-far projection.

Diff3D.look_at! — Method
look_at!(camera::AbstractCamera, target; up=nothing) -> camera

Aim camera at the world-space target. As in three.js Object3D.lookAt for cameras, rotation is set so that the local -z axis points at target with the world-space up hint up, accounting for the parent's world rotation.

Without up, a rotation_driven camera uses camera.up as the world-space hint (three.js camera.up). A target-aimed camera (not rotation_driven) keeps the world up direction its view already uses: its up field is in its parent's frame, so this equals three.js for an unparented camera or a parent without rotation. A target-aimed camera also stores the parent-space target (and, when up is given, the parent-space up) that reproduce this aim, so its view matrix equals the view implied by the new rotation.

Diff3D.stereo_update! — Method
stereo_update!(stereo::StereoCamera, camera::PerspectiveCamera) -> stereo

Update the left/right eye cameras from camera as three.js StereoCamera.update does. Each eye is camera shifted by ∓eye_sep/2 along its world right axis, with parallel view directions, and uses an off-axis (asymmetric) frustum that converges at camera.focus: the eye projections equal three.js's with the near-plane shift ±(eye_sep/2)·near/focus. The shift is stored as the eyes' film_offset (in mm of film_gauge), so projection_matrix and every renderer reproduce it. The eyes copy fov, aspect, near, far, zoom, focus and film_gauge; as in three.js, the vertical part of an enabled view offset of camera is kept and its horizontal part and film offset are replaced by the stereo frustum.
